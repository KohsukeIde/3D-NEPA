## Why This Phase Exists

Phase 0 showed positive internal denoising-time retrieval, but it did not prove transferable object representations. Phase 0.5 is therefore a hardening and shortcut-control phase, not a full pretraining run.

The goal is to decide whether Vector C deserves Phase 1, using both:

1. held-out internal dynamics;
2. minimal ScanObjectNN linear transfer and corruption robustness.

## Implemented Controls

- Train noise is stochastic by default (`deterministic_train=false`).
- Eval remains fixed and reproducible (`fixed_eval=true` in evaluation datasets).
- Explicit train/val/test split files are generated by `noise_nepa/data/write_split_files.py`.
- Partial split specification is rejected: train, val, and eval split files must be supplied together.
- Split files now fail on unresolved entries instead of silently skipping missing files.
- Training/validation fallback now splits at file level rather than augmented-sample level.
- Shared-epsilon denoising trajectories are supported with `epsilon_mode=shared`.
- New baselines:
  - `time_only`: predictor sees time pair but no latent state.
  - `z_shuffled`: predictor sees another sample's latent state.
- Retrieval and semigroup evals now include `time`, `no_time`, `shuffled_time`, `time_only`, `z_shuffled`, and `identity`.
- Metrics now include margin, effective rank, latent variance, and cosine-to-current/target.
- Variance logging uses `unbiased=False` to avoid batch-size-1 NaNs.

## Interpretation

Phase 0.5 confirms that Noise-NEPA can learn the internal denoising-time game under stronger controls:

- `time` beats `no_time`, `shuffled_time`, `time_only`, and `z_shuffled` on same-shape retrieval.
- Shared-epsilon semigroup direct/rollout retrieval is clearly above no-time and shortcut baselines.
- The main shortcut loophole is not completely gone: noise-level retrieval remains high for `z_shuffled` (`0.70` vs `0.76`), so same-shape noise-level retrieval alone is not enough evidence of useful state-conditioned representation.

However, the minimal downstream test is negative:

- ScanObjectNN PB-T50-RS linear is only around `34%`.
- The `time` checkpoint is not better than no-time, time-only, z-shuffled, or random encoder.
- Jitter/drop50 robustness also does not improve over random/shortcut baselines.

This means the internal dynamics objective is learnable, but the learned SimplePointEncoder representation is not yet useful for object-level transfer.

## Current Decision

Do not proceed to expensive full pretraining on the current SimplePointEncoder Noise-NEPA route.

Under the criteria below, Vector C should be removed from the AAAI main route unless the next iteration changes the representation pressure, not merely the internal retrieval metric. The most likely issue is that decoder-free global Gaussian latent transition can solve the denoising-time game without learning transferable local/object geometry.

Reasonable next actions are narrow:

1. archive this as a diagnostic result;
2. optionally test one stronger frozen/pretrained backbone feature extractor if already available;
3. do not spend multi-day compute on this SimplePointEncoder variant;
4. shift the main-theme search toward a route where the internal objective and downstream object representation are aligned from the start.

## Continue / Kill Criteria

Continue only if at least two lines of evidence are positive.

Internal dynamics:

- held-out same-shape retrieval: `time > no_time + 10pt`;
- `time > time_only + 5pt`;
- `time > z_shuffled + 5pt`;
- margins are positive or at least clearly better than shortcut baselines.

Representation:

- ScanObjectNN PB-T50-RS linear probe is at least `50%`, ideally `55%+`;
- clean is not below a weak scratch/random baseline;
- jitter/drop50 robustness is clearly better than baselines.

Semigroup:

- shared-epsilon rollout is better than no-time/identity;
- rollout does not collapse to current-view or identity-like behavior.

Kill Vector C as an AAAI main route if:

- `time_only ~= time`;
- `z_shuffled ~= time`;
- held-out retrieval margin disappears;
- ScanObjectNN linear is `<45%`;
- noisy/sparse robustness does not beat baselines;
- shared-epsilon semigroup is effectively random.
